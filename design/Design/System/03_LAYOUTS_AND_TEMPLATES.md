# RoofHub Design System — 03 Layouts & Templates

## 1. Responsive breakpoints

Reference breakpoints (framework may map to nearest standard value):

- Mobile: `< 640px`
- Large mobile/small tablet: `640–767px`
- Tablet: `768–1023px`
- Desktop: `1024–1439px`
- Wide: `>= 1440px`

Design mobile-first. Do not simply shrink desktop layouts.

## 2. Section rhythm

Standard sequence:

- Header.
- Hero/introduction.
- Proof/context/trust.
- Main task/content/tool.
- Supporting evidence/details.
- Related next steps.
- CTA (where appropriate).
- Footer.

Not every page needs every section. Remove sections that do not add value.

Section spacing:

- Hero: 80–112 px vertical desktop; 56–72 px mobile.
- Major feature/content: 64–96 px desktop; 48–64 px mobile.
- Standard block: 48–64 px desktop; 40–48 px mobile.
- Utility/meta: 24–40 px.

## 3. Reusable sections

Approved building blocks:

- Hero — editorial.
- Hero — tool-first.
- Hero — split image/content.
- Trust/evidence strip.
- Feature grid (2/3/4 cards).
- Tool launcher grid.
- Result summary.
- Methodology/evidence block.
- Content with sidebar.
- Comparison table.
- Step-by-step process.
- FAQ.
- Related resources.
- Image + content feature.
- Quote/enquiry prompt.
- Full-width CTA.

Agents should compose pages from these sections before inventing a new pattern.

## 4. Page templates

### Homepage

Recommended anatomy:

1. Brand/value hero.
2. Fast paths: Price / Measure / Identify / Plan.
3. Why RoofHub / methodology/trust.
4. Featured tool or live example.
5. Core roofing decisions/topics.
6. Guides/research.
7. Optional provider-help explanation.
8. CTA/footer.

### Pricing authority page

1. Clear H1 + dated NZ context.
2. Quick answer/range (with assumptions, GST basis).
3. Pricing calculator/tool entry.
4. Cost drivers.
5. Example scenarios.
6. What is/isn't included.
7. Regional/material/complexity considerations.
8. Methodology/sources.
9. FAQs.
10. Ask RoofHub CTA.

### Tool / calculator page

1. H1 and one-sentence purpose.
2. Tool above the fold or immediately after short explanation.
3. Result block.
4. How it works / methodology.
5. Assumptions and limitations.
6. Related tools/guides.
7. Optional enquiry CTA.

### Guide / article

1. Breadcrumbs.
2. H1, intro, reviewed/updated metadata.
3. Optional answer summary.
4. Main reading column.
5. Tables/images/callouts when useful.
6. Sources/methodology where technical.
7. Related guide/tool links.
8. Optional contextual CTA.

### Material/system page

1. What it is.
2. Where it tends to fit / not fit.
3. Core properties and constraints.
4. Cost/installation context where evidence exists.
5. Maintenance/durability with sourced wording.
6. NZ environmental considerations.
7. Compare alternatives.
8. Relevant tools/guides.
9. Sources.

### Repair vs replacement / decision page

1. Symptoms/problem framing.
2. Decision factors.
3. Preliminary self-assessment or photo tool.
4. Repair vs replacement table.
5. Situations requiring inspection/specialist.
6. Pricing implications.
7. Next step CTA.

### Contact / Ask RoofHub

Short, context-aware flow. Reuse data already generated by tools. Do not make users retype measurements/material/estimate already known in session.

## 5. Layout rules

- Use asymmetry sparingly; maintain obvious alignment.
- Do not use full-bleed text paragraphs except deliberate hero text.
- Alternate background tints only when they clarify section boundaries.
- Do not create a “striped page” of different background colours.
- Keep primary content in a stable left/right rhythm.
- Sidebars are for genuinely secondary content such as TOC, methodology or related tools.

## 6. Responsive behaviour

- Two-column layouts normally stack to one column below tablet.
- Preserve important action/result before supporting illustration on mobile.
- Tables become horizontal scroll, stacked comparison cards, or simplified views depending information density.
- Never hide important assumptions/exclusions on mobile.
- Sticky tool/result summary is acceptable if it does not obscure content.
- Avoid fixed-height content sections on small screens.

## 7. Accessibility

- Target WCAG 2.2 AA.
- Normal text contrast at least 4.5:1.
- Large text at least 3:1.
- All interactive controls keyboard accessible.
- Persistent, visible focus states.
- Minimum 44 × 44 px touch target where practical.
- Use semantic headings in order.
- Alt text describes information, not decoration.
- Do not encode meaning only with colour.
- Respect `prefers-reduced-motion`.

## 8. Motion

Motion should be functional and restrained:

- 120–200 ms for hover/focus.
- 180–280 ms for drawers/accordions.
- Use ease-out entering; ease-in exiting where appropriate.
- Avoid parallax, constant floating, decorative looping animation and large scroll-jacking effects.
