# RoofHub Design System — 04 Content & UI Rules

These rules make the visual system fit the RoofHub business model rather than becoming a generic template.

## 1. Voice

RoofHub should sound:

- Practical.
- Trustworthy.
- Calm.
- Specific.
- Evidence-led.
- Helpful to non-experts without being simplistic.

Avoid:

- Hard-sell language.
- Contractor-style claims such as “best roofers in NZ” unless objectively supportable.
- Unqualified superlatives.
- False certainty from image analysis, measurements or pricing.
- AI hype language.

## 2. Page introductions

Good page intro pattern:

- H1 directly matches the user's task/question.
- 1–2 sentence explanation.
- Useful answer/tool begins quickly.

Do not put 500 words of SEO introduction before a calculator or answer.

## 3. Pricing presentation

Always state where applicable:

- NZD.
- Whether GST is included/excluded.
- Material-only vs installed.
- Range rather than false precision.
- Major exclusions (scaffold, removal, disposal, flashings etc.).
- Date/source/methodology where price guidance is published.

Unknown items must not silently become zero.

## 4. Measurement / analysis presentation

Use labels such as:

- `Preliminary estimated roof area`.
- `Likely material`.
- `Visual indicators suggest…`.
- `Based on the supplied image/plan`.

Do not use:

- `Surveyed area` unless actually surveyed.
- `Certified diagnosis` without a qualified inspection.
- Definitive structural/compliance claims from model inference.

## 5. Evidence and sources

Technical claims should expose supporting evidence without making the page feel academic.

Preferred UI patterns:

- Small `Sources & methodology` section.
- Source links next to specialist claims/tables where useful.
- Updated/reviewed dates.
- Clear distinction between manufacturer documentation, regulation/guidance, industry material and RoofHub modelling.

## 6. Conversion

RoofHub gives value before asking for contact information.

Preferred sequence:

`Answer / result → explanation → optional next step → Ask RoofHub`

Avoid:

`Teaser → form gate → answer`.

## 7. Tool continuity

Where a user moves between tools/pages, preserve useful context when technically/privacy appropriate:

- Roof area.
- Pitch.
- Material.
- Location/region.
- Price result.
- Uploaded-analysis summary.
- Unknowns.

The user should not repeatedly enter the same information.

## 8. Data-heavy UI

- Use Sage as the primary supporting data colour family.
- Terracotta highlights the key series/action only.
- Neutral greys handle comparison/background series.
- Include units on axes/values.
- Show ranges and uncertainty visually when relevant.
- Ensure charts remain understandable without colour.
